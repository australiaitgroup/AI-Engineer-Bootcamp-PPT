02
为什么需要这节课

Demo 跑通 ≠ 能上生产

Demo 里 Agent 顺利跑完一次，你很兴奋。但生产环境要面对的是:它要跑一万次、有人会恶意输入、它会幻觉、API 会挂、它有删数据的权限。

Demo 心态
  • 跑通一次就庆祝
  • 输入都是"乖"的
  • 出错了人在旁边盯着
  • 权限随便给，图省事
Production 现实
  • 7×24 无人值守，错一次代价真实
  • 会遇到 Prompt Injection 攻击
  • 会幻觉、会无限循环、会超时
  • 权限越大，翻车面越大
⚠️ Anthropic 的核心建议:"先找最简单的方案，只在必要时才增加复杂度。" 能用 workflow 解决就别上 agent，能调 API 就别用 Computer Use。
03
Computer Use

让 AI 像人一样操作电脑

Claude 不靠 API，而是看屏幕截图 → 识别 UI 元素 → 移动鼠标/点击/打字 → 再截图验证结果。它操作的是界面，跟人一模一样。

✅ 适合用
  • 自动化没有 API 的遗留系统(老的企业内部系统，只有 Web UI)
  • 跨多个应用的工作流:邮件→Excel→提交系统
  • UI 测试自动化:回归测试、表单填写
❌ 不要用
  • 有 API 的系统——直接调 API 更快、更可靠、更便宜
  • 高频、低延迟要求的任务(它一步要 3–5 秒)
  • 不可逆的高危单步操作没有人审
📌 判断口诀:有 API 调 API，没 API 才考虑 Computer Use。 操控像素永远是下策，不是首选。
04
核心机制

Computer Use 的工作循环

本质是一个闭环:Claude 出主意，你的代码动手，截图反馈，循环到任务完成。截屏 → 识别 → 操作 → 验证。

1
请求截屏

Claude 说"给我看现在的屏幕"。

→ 你的代码截屏
2
分析画面

识别按钮、输入框、文本的位置。

→ Claude 视觉理解
3
发出指令

move_mouse(x,y) / click() / type("…")。

→ Claude 决策
4
执行操作

真实移动鼠标、点击、键入。

→ 你的代码执行
5
再次截屏

截新屏，验证刚才那步成没成。

→ 反馈回 Claude
6
循环 / 收尾

没完成就回到第 2 步，直到任务结束。

→ 直到完成
💡 关键洞察:每一步都靠"截图验证"来纠错——这也是为什么它慢，但只要设计好就能自我修正。

约 20 分钟 07
生产安全清单 · 必须做 ✅

Agent 不是 Demo，这 7 条是底线

检查项说明实现方式
最大迭代次数防止 Agent 陷入无限循环max_iterations = 10
工具调用超时单个工具不能一直挂着timeout = 30s
Token 上限防止单次调用烧太多钱max_tokens = 10000
输入过滤检测 Prompt Injection正则快筛 + LLM 复判
输出检查敏感信息不能泄露PII 检测 + 关键词过滤
操作确认危险操作需人工审批发邮件 / 删数据前暂停
完整 Trace每一步都可追踪复盘LangSmith / Langfuse / OTel
✅ 记法:三个上限(迭代/超时/Token) + 三道闸(输入/操作/输出) + 一条命脉(Trace)。
07
生产安全清单 · 绝不要做 ❌

这 5 件事，做了迟早出大事

  • ❌ 给 Agent 不受限的数据库写权限——一次幻觉就能写花生产库。
  • ❌ 让 Agent 自主发邮件 / 发消息——对外动作至少要人工确认。
  • ❌ 在没有 sandbox 的环境里执行 Agent 生成的代码。
  • ❌ 把 API Key 写进 System Prompt——会被 injection 套出来。
  • ❌ 上线前不做 Red-teaming(对抗测试)就直接放生产。
🔒 一条总原则——最小权限(Least Privilege):Agent 只拿完成任务最少的权限，能只读就别给写，能给沙箱就别给真环境。
08
Guardrails

三道闸 + 人在回路

护栏不是可选项，是必须项。把它想成给 Agent 加的"进门安检、动手前审批、出门复检"。

① 输入过滤
Input Filter

用户消息进来先安检:检测 Prompt Injection、可疑指令，拦在最前面。

② 操作确认
Action Approval

危险动作(发邮件、删数据、执行代码)暂停，等人点头才放行。

③ 输出检查
Output Check

回复出门前复检:PII、密钥、敏感关键词一律拦截。

🧍 贯穿三道闸的是 Human-in-the-loop(人在回路):Anthropic 明确建议——在不可逆操作前设检查点，让人来批。
09
Guardrail ① 实现

输入过滤:挡住注入

def check_input(user_message): # 1. 正则快筛常见注入模式 injection_patterns = [ r"ignore previous instructions", r"you are now", r"system prompt", ] for pattern in injection_patterns: if re.search(pattern, user_message, re.IGNORECASE): return False, "检测到可疑输入" return True, "OK"
🧪 正则是第一层快筛:便宜、快，但容易漏(改个说法就绕过)也容易误报。所以还需要第二层——见 FAQ 的"两层过滤"。
10
Guardrail ③ 实现

输出检查:别泄密

def check_output(agent_response): # 检查是否泄露敏感信息 pii_patterns = [ r"\d{3}-\d{2}-\d{4}", # SSN 社保号 r"sk-[A-Za-z0-9_\-]{20,}", # OpenAI 密钥 r"sk-ant-[A-Za-z0-9_\-]{20,}", # Anthropic 密钥 r"\b\d{16}\b", # 信用卡号 ] for pattern in pii_patterns: if re.search(pattern, agent_response): return False, "输出包含敏感信息" return True, "OK"
🔑 密钥格式会变(如 OpenAI 新版 sk-proj-…),正则要放宽并定期更新;同时记得把自家密钥、内部 URL、客户 PII 都纳入黑名单。
11
Guardrail ② 实现

操作确认:危险动作先暂停

def confirm_action(action_type, details): # 危险操作清单——动手前必须人审 DANGEROUS = ["send_email", "delete_data", "execute_code", "make_payment", "db_write"] if action_type in DANGEROUS: # 暂停，等人工确认(人在回路检查点) approval = wait_for_human_approval(action_type, details) return approval return True # 非危险操作自动通过
自动放行

读取、查询、截屏、生成草稿——可逆、低风险，不打扰人。

必须人审

发邮件、删数据、转账、写库、跑代码——不可逆、对外、动钱。

约 15 分钟 13
Agent Ops · 可观测性

看不见，就管不了

生产 Agent 必须每一步可追踪:输入、每次工具调用、token、延迟、最终输出，全程留痕。出问题能定位到是哪一步、哪次调用。

LangSmith
商业 · LangChain 生态

对 LangChain / LangGraph 原生支持最好,自带 agent 图可视化和人工标注队列。

Langfuse
开源 · 自托管

开源主流(MIT),tracing + prompt 版本管理 + 评估;有数据驻留要求时首选。

OpenTelemetry
标准 · 厂商中立

GenAI 语义规范成为通用标准;Datadog / New Relic 也在加 LLM 监控面板。

📊 必盯指标 + 告警阈值示例:错误率 > 5%、P95 延迟 > 60s、单任务 token > 上限 80%、人审拒绝率突增 → 立即告警。

Agent Ops · 降级策略

挂了怎么办?提前想好

生产里依赖一定会抖:LLM API 会 5xx、工具会超时、截图会失败。降级(Graceful Degradation)就是让系统"坏得体面"。

故障场景降级策略
LLM API 挂了 / 限流指数退避重试 → 切备用模型 / 备用区域 → 仍失败则转人工队列并告警
工具调用超时单工具 timeout=30s → 重试 1–2 次 → 标记失败、跳过或回滚，绝不静默挂起
Agent 无限循环max_iterations 触顶 → 强制中止 → 保存现场 trace 供复盘
疑似幻觉 / 越界关键结果做二次校验(规则或第二个模型)→ 不确定就交人审，不自动执行
🛟 原则:失败要响、要可恢复、要留痕。 最差的情况不是报错，而是 Agent 默默做错还没人知道。

写一份 Production Deployment Plan

为你自己的 ISA Agent 写一份上线方案。不用很长，但下面四块都要落到具体数字和规则。

① 安全配置

给出 max_iterations、timeout、token limit 的具体值,并说明为什么是这个值。

② Guardrails

写出输入过滤规则、输出检查规则,以及需人工确认的操作清单。

③ 监控

④ 降级策略

✍️ 交付物:一页纸即可。重点是每个数字都有理由、每个危险操作都有人审。
15
常见问题

现场最常被问的两个

Q:Computer Use 延迟多高?

每次截屏 + 分析 + 操作约 3–5 秒,一个 10 步任务约 30–50 秒。比人慢，但能 7×24 不间断、且(设计好的话)不出错。所以它适合"慢而稳"的无人值守场景，不适合实时交互。

Q:Guardrails 会误杀正常请求吗?

会。正则容易误报。建议两层:第一层正则快筛明显注入(便宜快),第二层用 LLM 判断(准但慢)。只有两层都判危险才拦截,既降误杀又不漏网。

🧊 补充:Anthropic 官方在 Computer Use 截图上已内置 prompt-injection 分类器——你的 Guardrails 是在它之上再加一层，纵深防御。
16
小结

带走这三句话

  • Computer Use 适合无 API 系统的自动化——看屏幕、动鼠标、截图验证;有 API 永远优先 API。
  • Guardrails 不是可选项，是必须项——三道闸(输入/操作/输出)+ 三个上限(迭代/超时/Token)+ 完整 Trace。
  • Agent 上生产的核心原则:最小权限 + 完整可观测 + 人在回路——尤其是不可逆操作前，一定留检查点给人。
