为什么选型是大事

选 SDK = 选一条不好回头的路

Agent SDK 不是一个库那么简单,它决定了你的模型绑定、部署方式、团队学习成本、未来迁移难度。选错了,半年后想换要伤筋动骨。

🔒 模型锁定

绑死某家模型,议价权和灵活性都没了。

💰 成本结构

不同 SDK 的 token 用法、并发模型,账单差很多。

👥 团队技能

你的团队用 Python 还是 Java?社区文档够不够?

☁️ 部署环境

已经在 GCP / AWS 上?会强烈影响首选。

⚖️ 一句话:技术选型的成本不在写代码时,而在两年后想换的时候。 所以这节课强调"按约束选",而不是"按热度选"。
03
三家一句话画像

它们眼里的"agent"根本不是一个东西

OpenAI
对话处理器 + 委派

agent 是会对话、会把任务交给别的 agent 的处理器。核心是 Handoffs 委派链,轻量、灵活。生态最大,但把你绑在 OpenAI 模型上。

Claude
会用电脑的助手

agent 是拿到一台电脑、一堆工具的用户:能读写文件、跑 bash、搜网、调 MCP。适合编码助手和深度 OS 操作。流式体验丝滑。

Google ADK
分布式软件组件

agent 是分布式系统里的一个组件:用图定义多 agent 如何协作。最工程化、最企业级,且模型无关。

🧠 记住这三句画像,后面所有代码和取舍都能对上号:OpenAI 委派、Claude 用电脑、Google 搭系统。

06
设计哲学

为什么代码写法差这么多?

三家 SDK 的 API 手感差异,全都源自它们对 agent 的底层设定。理解哲学,比记 API 更重要。

OpenAI:对话 + 委派
  • 核心是一个个 Agent 和它们之间的 Handoff
  • 写法像"搭一条对话委派链"
  • guardrails 与执行并行跑,不通过就快速失败
Claude:给 agent 一台电脑
  • 内置文件/bash/web 工具 + MCP 接万物
  • 写法像"配一个能动手的助手 + 钩子"
  • hooks 在生命周期节点拦截,天然做 guardrail
🏗 Google ADK:把 agent 当分布式系统的软件组件,用图定义谁调用谁、如何并行——最结构化,也最适合复杂企业编排。
07
深入 · OpenAI Agents SDK

四个原语拼出一切

Agents

带 instructions + 工具的基本单元。

Tools

@function_tool 装饰器,函数即工具。

Handoffs

把任务连同完整历史交给另一个 agent。

Guardrails

输入/输出校验,与执行并行,失败即停。

  • 内置 tracing:LLM 生成、工具调用、handoff、guardrail 全记录,Traces 面板可视化调试。
  • 优势:生态最大、上手快、语音支持强;代价:默认锁 OpenAI 模型,vendor 依赖较重。
👍 一句话:最像"标准答案"的 SDK——想快速起步、跟着最多教程走,它最省心。
08
代码 · OpenAI

OpenAI:函数即工具,一行运行

from agents import Agent, Runner, function_tool @function_tool def get_weather(city: str) -> str: return f"{city} 晴,24°C" # 真实中接天气 API agent = Agent( name="Weather Assistant", instructions="你是天气助手,需要时调用工具", tools=[get_weather], ) result = Runner.run_sync(agent, "东京今天天气怎么样?") print(result.final_output)
🔎 看点:函数加个装饰器就成工具,Runner 一行跑起来。多 agent 时给 Agent(..., handoffs=[other]) 即可委派。
09
深入 · Claude Agent SDK

给 agent 一台电脑 + 一堆钩子

内置工具

文件读写、bash、web search/fetch,开箱即用。

Subagents

子代理各有独立上下文/工具/模型,并行分工。

Hooks

在工具调用前后、出错时拦截,天然做 guardrail。

Sessions + MCP

持久会话 + MCP 一等公民,任何 MCP 工具即插即用。

  • 人在回路:工具使用循环内置可选的 human-in-the-loop 检查点。
  • 优势:MCP 生态、深度 OS 操作、流式体验丝滑;代价:锁 Claude 模型,社区相对新。
👍 一句话:最适合"编码助手 / 深度工具型 agent",尤其你已经在用 MCP 时,几乎零集成成本。
10
代码 · Claude

Claude:内置工具 + 流式循环

import asyncio from claude_agent_sdk import query, ClaudeAgentOptions async def main(): options = ClaudeAgentOptions( system_prompt="你是天气助手", allowed_tools=["WebSearch"], # 内置/或接 MCP 工具 permission_mode="acceptEdits", # 可插入人审检查点 ) async for msg in query(prompt="东京今天天气怎么样?", options=options): print(msg) # 流式输出每一步 asyncio.run(main())
🔎 看点:工具很多是内置的(WebSearch/文件/bash),或直接挂 MCP server;async for 天然流式,每步实时可见。示意代码,以官方文档为准。
11
深入 · Google ADK 2.0

把 agent 当软件组件来"搭系统"

Code-first

用代码精确控制行为、工具、编排。

多语言

Python / Java / Go / TypeScript 全支持。

图式多 agent

用图定义子 agent 如何协作,逻辑清晰可靠。

模型无关

Gemini / Claude / Ollama / vLLM / LiteLLM 都能接。

  • 企业部署:原生 Cloud Run / Vertex / Gemini Enterprise,A2A 协议做跨 agent 通信。
  • 优势:模型灵活、多语言、企业级编排;代价:抽象较重、中文资料少、最贴 GCP 生态。
👍 一句话:已经在 GCP、团队用 Java/Go、要搭复杂多 agent 系统——ADK 是三家里最顺的。
12
代码 · Google ADK

Google ADK:声明式,最结构化

from google.adk.agents import Agent def get_weather(city: str) -> dict: return {"status": "ok", "result": f"{city} 晴,24°C"} root_agent = Agent( name="weather_agent", model="gemini-2.5-flash", # 也可换 Claude / 开源模型 instruction="你是天气助手,需要时调用工具", tools=[get_weather], ) # 运行: adk run 或用 Runner 编排多 agent
🔎 看点:结构化返回(dict)是 ADK 的习惯,便于图式编排;model= 一行就能换模型——这是三家里独有的灵活。

最容易被忽略的一条

Vendor Lock-in:绑得有多死?

这是选型报告里技术总监最关心的一条。三家在"模型绑定"上的立场,直接决定你未来的议价权和迁移成本。

OpenAI
锁定较重

默认深度绑定 OpenAI 模型与生态,tracing 等也偏自家。换模型要绕路。

Claude
锁定 + 但 MCP 开放

模型锁 Claude,但工具层靠 MCP 开放标准,工具生态可跨平台复用。

Google ADK
模型无关

唯一原生模型无关:Gemini/Claude/开源随便换。但框架本身贴 GCP。

🔑 反直觉更新:三家里最"不锁模型"的反而是 Google ADK——但它把你更绑在 GCP 部署上。锁定从来不会消失,只是换个地方。

怎么选 · 决策树

三个问题,选出你的 SDK

Q1:已经在 GCP?
团队用 Java/Go?

或要搭复杂多 agent 系统、要模型自由切换 → Google ADK。

Q2:做编码/OS 型 agent?
重度用 MCP?

或要丝滑流式、深度工具与人审 → Claude Agent SDK。

Q3:要快速起步?
看重生态与教程?

或做轻量委派链、需要语音、能接受锁 OpenAI → OpenAI Agents SDK。

💡 现实建议:先用你已有的云和团队技能筛掉一个,再在剩下两个里跑个小原型。别纸上谈兵,一个下午的 PoC 胜过十篇对比文。

常见误区

选型时最容易犯的错

  • "按热度选" —— GitHub star 多 ≠ 适合你的场景和团队。
  • "以为能轻松换" —— 除了 ADK,换模型/换框架成本都不低,早想清楚。
  • "忽略团队语言" —— 团队是 Java/Go 的,硬上纯 Python 框架会很痛。
  • "只看代码量" —— 起步少不代表维护省;可观测性和调试同样重要。
  • "不做 PoC 就拍板" —— 一个下午的小原型,比任何对比表都可靠。
⚠️ 还有一条:别忽视"锁定换个地方"这件事——ADK 不锁模型但更贴 GCP,OpenAI 锁模型但生态最省心。没有免费的午餐。

小结

带走这三句话

  • 三家哲学不同:OpenAI 对话委派、Claude 给 agent 一台电脑、Google ADK 搭分布式系统——代码差异都源于此。
  • 没有最好,只有最适合:要模型自由→ADK;要 MCP/编码/OS→Claude;要生态/轻量/快起步→OpenAI。
  • 按约束选,用 PoC 定:先用云环境和团队语言筛,再跑小原型实测代码量/延迟/可控性,最后写进选型报告。
